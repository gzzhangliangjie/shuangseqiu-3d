## 2. 两条路线怎么选

| 对比项 | **路线 B：体验版（自用/内测）** | **路线 A：公开上架** |
|---|---|---|
| 谁能用 | 你 + 白名单里的体验成员（扫码） | 全部微信用户（搜索、分享、扫码） |
| 微信审核 | 不需要 | 需要（正常 1~3 个工作日） |
| 小程序备案 | 不需要 | **必须**，且管局通过后才能发布 |
| 软著 | 不需要 | 需要（见 §4.4） |
| 内容改造 | 不需要 | **必须**（见 §3） |
| 耗时 | 1 小时 | 2~4 周（备案/软著是长尾） |
| 风险 | 无（不公开传播即可） | 内容涉彩票，存在账号处罚风险 |

**建议顺序**：先走 B 把「真机能跑起来」这件事闭环（顺便暴露低端机性能问题），再决定要不要为 A 付出改造 + 资质成本。

## 3. 路线 B：体验版（先做这条）

### B0. 注册小游戏账号，拿 AppID（唯一需要你本人操作的一步）
1. 打开 <https://mp.weixin.qq.com> → 注册 → **小程序**（小游戏也是在这里注册）。
2. 主体选**个人**即可（企业主体才有虚拟支付，本项目不需要）。
3. 注册后进后台 → 「设置 → 基本设置」填名称、头像、简介；**服务类目必须选「游戏」，子类目选「休闲游戏」**。
4. 在「开发 → 开发管理 → 开发设置」抄下 **AppID**。
   - 注意：一个邮箱只能注册一个小程序；个人主体名下小游戏数量有上限，以后台提示为准。
   - AppID 拿到后贴给我，或自己填进下一步。

### B1. 上传前自检（1 秒，已脚本化）
```bash
node miniprogram/preflight.js
```
检查 9 项，任何 `[FAIL]` 都要先修再上传：

| # | 检查项 | 为什么 |
|---|---|---|
| 1 | 14 个必备文件齐全 | 少一个真机就白屏 |
| 2 | **产物是否比真源旧** | 改了 `index.html` 忘跑 `build.js`，传上去的是旧逻辑 |
| 3 | 主包 ≤ 4 MB | 超了直接不让上传，必须分包 |
| 4 | 文件后缀在上传白名单内 | 白名单外文件会被**静默丢弃**，只在真机报错 |
| 5 | `node --check` 全量语法 | 编译期错误在开发者工具里不一定挡住上传 |
| 6 | 无 `eval` / `new Function` | 微信禁止运行时动态执行代码 |
| 7 | `compileType=game`、竖屏、AppID 非占位 | 配置错会导入成普通小程序 |
| 8 | `__SIM_REMOTE=false` | 确认运行期零网络，不用配合法域名 |
| 9 | 列出全部 `wx.*` API 和最低基础库 | 用来定后台「最低基础库版本」 |

当前结果：**0 失败 / 1 警告**（警告就是 AppID 还是 `touristappid`）。

### B2. 写入 AppID
改 `miniprogram/project.config.json` 的 `appid`（`description` 已改为「自用体验版」）：
```json
{ "appid": "wxXXXXXXXXXXXXXXXX", "compileType": "game" }
```
改完再跑一次 `node miniprogram/preflight.js`，警告应消失。

### B3. 导入项目
微信开发者工具 → 导入 → 目录**选 `E:\shuangseqiu-3d-sim\miniprogram`**（不是仓库根目录）→ 类型自动识别为「小游戏」。
首次打开若报基础库不兼容，在「详情 → 本地设置」把调试基础库调到 3.x 稳定版。

### B4. 模拟器自测
- 看 Console 有无红错；`game.json` 竖屏是否生效。
- 打开「性能面板」看 FPS / 内存 / DrawCall。**基线：中端安卓 FPS ≥ 30，内存峰值 < 300 MB。**
- 逐项点：开始摇奖 → 6 红 + 1 蓝出完 → 分布页 → 选号页 → 记录页 → 返回 3D 页。

### B5. 真机调试（「预览」扫码）
重点看这 7 项，**任何一项不过都先别上传**：

| 项 | 合格线 | 不过怎么办 |
|---|---|---|
| 首屏白屏 | < 3 s | `three.js` 1.24 MB 解析是主因，可把 `ssq-data` 拆分包 |
| 竖屏安全区 | 上下不被刘海/小白条遮挡 | 调 `hud.js` 的顶部/底部安全区偏移 |
| 触摸拖拽视角 | 单指拖动顺畅、不误触按钮 | `hud.js` 命中区判定 |
| 摇奖完整一局 | 6 红 + 1 蓝全部出球入位 | — |
| **音效** | 点「开始摇奖」有提示音、搅拌有嗡鸣 | 见下方「音频兜底」 |
| 切页 | 分布/选号/记录页可进可回，回 3D 正常 | `pages.js` 的 `isDrawPage` |
| 低端机 FPS | ≥ 30，无掉帧卡死 | 关抗锯齿（已是 false）、降纹理 |

> **音频兜底**：小游戏里 `AudioContext` 走 `wx.createWebAudioContext()`（`adapter.js` 第 246 行）。
> 如果真机出现「点开始摇奖无反应」或控制台报音频错误，是 `game-logic.js` 的 `AudioFX.ensure()` 在 `buildSamples()` 抛异常（`createBuffer` 采样率不被支持）。
> 修法：在真源 `index.html` 对应位置把 `ensure()` 整体包一层 `try { … } catch (e) { broken = true; return null; }`，重跑 `build.js`——静音但不影响摇奖。

### B6. 上传开发版
工具栏右上「上传」→ 版本号 `1.0.0`，备注写清本次改动 → 上传成功即成为「开发版」。

「管理 → 成员管理 → 体验成员」添加微信号（数量上限以后台显示为准），成员扫码即可用。

### B8. 迭代循环（固定套路）

## 4. 路线 A：公开上架（⏸ 暂缓，将来想公开时再执行）

### A1. 主体与账号
- 个人主体：可发布免费游戏，广告变现（IAA），**不能开虚拟支付**。
- 企业/个体工商户：可开内购，但需版号（见 §4.4）。
- 本项目定位为**免费、无内购**，个人主体足够。

### A2. 类目与命名
- 类目：**游戏 → 休闲游戏**。类目与实际内容不符是最常见驳回原因之一。
- 名称规则：
  - 不得使用「双色球」「福彩」「彩票」等彩票专有词/他人商标；
  - 建议取名方向：`3D 摇奖机`、`幸运摇号`、`物理摇奖演示`、`六加一摇奖`；
  - 名称需与后续提交的**软著名称一致**，否则要额外提供授权/说明。

### A3. 内容合规改造清单（**硬性前置，按文件逐条改**）

| 文件 | 现有内容 | 改法 |
|---|---|---|

| `index.html` | 「双色球」出现 8 处 | 改「6+1 号码」「摇奖演示」 |

| `index.html`（贴图） | 底座福彩标志牌、墙面文字纹理 | 换成**自绘中性标识**（几何图形 + 项目名），不留任何彩票机构元素 |

### A4. 资质准备

| 材料 | 何时必须 | 周期 | 本项目动作 |
|---|---|---|---|
| **小程序备案**（工信部，微信后台代为申报） | 所有小游戏发布前**必须**，且管局通过后才能点「发布」 | 1~3 周 | 后台「小程序备案」按主体填资料 |
| **计算机软件著作权**（软著） | IAA 情形下，名称含英文/"软件"、涉品牌合作时**强制**；实践中普遍被要求 | ~30 个工作日（可加急） | 建议提前办，著作权人须与账号主体一致 |

| **隐私保护指引** | 所有小游戏**必填** | 即时 | 声明 `getSystemInfoSync`（设备/系统信息，用于分辨率适配）；本地存储说明为"仅存于本机" |

### A5. 技术达标检查
1. **包体**：主包 1.7 MB / 上限 4 MB，无需分包 ✅。
2. **首屏**：`three.js` 解析 + 场景构建是主要耗时，真机首屏目标 < 3 s；若超标，把 `libs/ssq-data.js` 改为分包 `wx.loadSubpackage` 延迟加载。
3. **基础库**：提审前在后台「设置 → 基本设置 → 最低基础库版本」设一个你真机验证过的版本（建议 2.30+）。
4. **网络**：保持 `__SIM_REMOTE = false`。若坚持保留 PC 联调代码，**建议在发布构建里整段删除** `adapter.js` 里的 `wx.request` 分支与 `src/simlog.js` 的 `fetch` 调用——审核员看到"连 127.0.0.1:8731"会当成未完成功能。
5. **性能**：低端安卓（如 4 GB 内存机型）跑完整一局，FPS 不低于 30，无 OOM。
6. **禁止项自查**：无 `eval` / `new Function` ✅、无诱导分享 ✅、无外链跳转 ✅、无广告位（暂未接入）✅。
7. **存档**：`wx.setStorageSync` 只存本机，不采集个人信息，隐私指引里说明即可。

### A6. 提审（后台「版本管理 → 开发版本 → 提交审核」）

| 必填项 | 填什么 |
|---|---|
| 游戏引擎 | 「其他引擎」→ 填 `自研 Three.js / WebGL`（或 `Three.js`） |
| 用户隐私保护指引 | 按 §4.4 填写并保存 |
| 适龄提示 | 8+ |
| 版本更新说明 | 「首个版本：3D 物理摇奖演示，支持摇奖动画、号码分布统计、本地记录」 |
| 游戏自审自查报告 | 官方模板，逐项勾选 + 签字 |
| 游戏内容介绍 / 截图 | ≥ 4 张清晰截图，**截图内不得出现彩票类字样** |
| 苹果开发者账号 | 必填（可填邮箱） |
| 宣传图 | 非必填 |

提交后：审核 1~3 个工作日（首版本不能用加急，加急需历史已过审版本 + 注册用户 > 5000）。

### A7. 发布与运维
1. 审核通过 → 微信「服务通知」提醒 → 后台点「提交发布」。
2. **前置条件**：小程序备案必须已通过，否则发布按钮不可用。
3. 发布方式：全量发布 / 分阶段发布（先放量 10% 观察崩溃率再全量）。
4. 回滚：后台「版本管理」可切回上一个已发布版本（不要清理历史版本记录）。
5. 后续每次迭代重复：`改 Web → build.js → 上传 → 提审 → 发布`，**小游戏没有热更新**。

## 6. 常见驳回原因 → 本项目对策（⚠️ 仅路线 A 适用）

## 7. 时间线与工作量

**路线 B（体验版）— 当前执行中**
```
✅ 工程自检 + 产物重建 + 配置改名      已完成
⬜ 注册小游戏账号（邮箱+手机+实名）   约 20 min（含验证等待）
⬜ 写入 AppID + preflight 复查         2 min
⬜ 导入开发者工具 + 模拟器自测        约 30 min
⬜ 真机预览（B5 的 7 项验收）          约 20 min
⬜ 上传 + 设体验版 + 加白名单          约 10 min
合计 ≈ 1.5 小时（从 AppID 到手算起）
```

**路线 A（公开上架）— ⏸ 已暂缓，仅备查**
```
第 1 天    ：内容改造（§3）+ build.js + 真机回归
第 1~3 天  ：软著材料提交（并行）、备案提交
第 3~5 天  ：提审材料准备（截图/自审报告/隐私指引）
第 5~8 天  ：提交审核（1~3 工作日）
第 2~4 周  ：等备案管局通过 → 发布
```
> 关键路径是**备案**，不是审核。内容改造越早完成，备案通过时就能立刻发。
