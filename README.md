# 双色球 3D 物理摇奖机

用 Three.js 复刻中国福利彩票双色球真实摇奖机（法国 RYO CATTEAU **Myosotis**），
**全程自己写的物理引擎**，没有预设号码或动画作弊：哪颗球被摇出，完全由物理决定。

单文件网页，无需构建：双击 `index.html` 即可（此方式走 CDN）。**入口落在「选号工具」页**
（`picker/index.html`），3D 摇奖机是它的子页，从选号页顶部「打开 3D 摇奖机」进入；
想直接开 3D 页，用 `index.html?raw=1`。推荐用本地 http 服务打开，
可走内置的 `_vendor/` 本地 Three.js，秒开且离线可用（见文末「Three.js 加载源」）。

## 结构对齐真机

依据中国福彩网 / 贵州福彩网公开资料，Myosotis 的结构为：

官方参数：整机高 2.02m × 宽 0.75m，**底座 0.77m / 搅拌室 0.83m / 预览架 0.42m**，
本版按此比例建模（1 单位 ≈ 0.296m），外观对照中国福彩网官方照片复刻。

| 部件 | 本项目实现 |
|---|---|
| 号码球预览架（0.42m） | 单排弧形透明管束立在搅拌室正上方（子午线金属环支撑），球停管内（红机 8 管×4+中心 1=33；蓝机 8 管×2=16），顶部入口导流锥 |
| 落球动作 | 预览架挡板滑开，球从竖管落入搅拌室顶部大开口 |
| 球状搅拌室（Ø70cm） | 两个半球 + 赤道接缝环，三个玻璃纬度带拼出顶部开口 + 下前方出球口 |
| 底部蓝座圈 | 玻璃球坐在深蓝圆台底座的座圈里（对照官方照片） |
| 两个双向旋转搅拌盘（专利 US6145836） | 左盘 3 杆 / 右盘 8 杆径向拨杆，反向旋转，切向拖带 + 盘面弹跳 |
| 出球口档杆 | 外凸金属短管 + 翻板阀，**开一颗、过一颗、立即关阀** |
| 出球轨道 | 底座侧透明 U 形滑槽（金色上沿、支撑柱），球滚下进入显示通道排队 |
| 底座（0.77m） | 深蓝圆台 + 福彩标志牌；出球时其余球持续搅拌（真机防堵原理） |

摇奖球真实尺寸为 Ø50mm（搅拌室的 1/14），为保证号码可读，3D 中取 Ø 视觉放大值。

## 流程

```
预览架挡板开 → 落球入搅拌室 → 双盘逆向搅拌 3s → 出球口档杆开
→ 球落到出球轨道 → 滚入显示通道排队 → 结果栏记录 → 重新搅拌 → 下一颗
```

红球机连开 6 颗，之后蓝球机开 1 颗，和真实开奖顺序一致。

## 物理引擎

- 固定步长 `1/120s`，重力 + 球球弹性碰撞（位置修正 + 冲量）+ 球面容器壁约束
- 搅拌 = 双盘反向切向力场 + 盘面随机弹跳（对应真机两个搅拌底盘）
- 出球 = 档杆开洞 + 向出口的导流力场，球被物理"带"出洞口
- 出球轨道 / 显示通道：沿斜面滚行 + 微坡排队，球挨球自然停靠

## 本地仿真验证

`sim_real.js`（项目根目录）是网页物理逻辑的镜像实现，用于在不打开浏览器的情况下验证整条流程：

```bash
node sim_real.js
```

实测结果：红球机 6/6 全部出球并入位（全程约 35s，接近真实直播节奏），蓝球机 1/1。

## 操作

- 「开始摇奖」：完整开奖流程
- 「重置」：球回到预览架
- 「选号工具」：打开历史分布分析页（需先启动 `node picker/sim_server.js` 获得完整功能）
- 左键拖拽旋转视角（滚轮缩放、右键平移已移除，避免移动端误操作）

## 技术栈

Three.js 0.160（importmap）+ 自写物理引擎 + CanvasTexture 号码球 + PMREM 自制影棚环境反射。

## 移动端 / 小游戏适配现状

渲染基线按手机真机设定，桌面端观感保持一致：

- 画质：关 MSAA、DPR 封顶 2、Basic 阴影 512²、玻璃壳半透明近似（不用 `transmission`）、
  球纹理 256×128、球用 `MeshStandardMaterial` + 18 段几何；不启用 Bloom 后处理。
- 纹理/内存：所有贴图绘制都用 `ctx.scale()` 保持原绘制坐标不变、只缩小 backing store。
  背景墙 4160×600 → 2048×295，环境图 1024×512 → 512×256，地板 512² → 256²，
  球壳 alphaMap 1024² → 512²；球贴图改为「单个 256×128 画布直接绘制」，
  不再生成 512×256 中间位图（49×2=98 个 canvas → 49 个）；
  49 颗球共用一份 `SphereGeometry`，两台机器共用一张 LOGO 纹理。
  CPU 侧离屏位图合计约 **53MB → 12MB（-77%）**，上传 GPU 的纹理内存同步下降
  （背景墙 / 球 / 地板 / alphaMap / LOGO 全部按新尺寸）。
- 分辨率：`Platform` 适配层统一取视口（Web 用 `window`/`visualViewport`，小游戏用
  `wx.getSystemInfoSync()` / `wx.onWindowResize`），`applySize()` 平台无关、两端同一套逻辑；
  `resScale` 按实时帧率在 1 → 0.6 之间动态降档。
- 3D 构图：`fitFov(aspect)` 按宽高比动态放宽垂直视角，保证两台机器在竖屏下完整入画；
  宽屏恒为 30°（原版构图不变）。
- HUD：`viewport-fit=cover` + `env(safe-area-inset-*)` 避让刘海/Home 条，
  窄屏（≤600px）/ 矮屏（≤480px）有响应式收缩。

## Three.js 加载源

`_vendor/` 内置完整 r160 副本（`three.module.js` + `controls/` + `environments/`）。importmap 按协议分流：

- 通过 **http(s)** 打开（推荐）：走 `_vendor/` 本地副本，秒开、离线可用，也是迁小游戏
  （不支持外部 CDN）的既定路径。
- **双击 `index.html`（file://）/ 预览沙箱**：ES module 无法 fetch 本地 `file://`（CORS），
  自动退回 CDN，**原有直接双击打开的能力不变**。

本地起服务：在项目目录执行 `python3 -m http.server 8000`，浏览器打开 `http://127.0.0.1:8000/index.html`
（会跳到选号工具，`/picker/index.html` 同页）；若要用选号工具的完整功能，改用 `node picker/sim_server.js`
（端口 8731，3D 页在 <http://127.0.0.1:8731/machine>）。

## 微信小游戏（自用，不发布）

`miniprogram/` 是可直接导入「微信开发者工具」的小游戏项目。**自用不需要上架审核**：
开发者工具里用测试号 / 无 AppID 模式打开，点「预览」扫码即可在自己手机微信里运行，
永远不点「上传 + 提交审核」就行。

### 目录与构建

```
miniprogram/
  game.js                 入口（adapter -> data -> simlog -> hud -> pages -> game-logic）
  game.json               竖屏 / 隐藏状态栏
  project.config.json     开发者工具项目配置（appid 占位 touristappid）
  adapter.js              DOM / canvas / 触摸 / 时间 / 音频 / wx storage / fetch 适配
  hud.js                  UI 表面：一张离屏 2D 画布 + CanvasTexture + 正交 quad（开奖页 HUD）
  pages.js                选号 / 分布 / 记录三个页面（自绘图表与控件，共用 hud 的同一张画布）
  build.js                构建脚本：ESM -> CommonJS + 抽取 Web 端算法，零第三方依赖
  libs/                   build.js 生成或复制：three r160 / OrbitControls / RoomEnvironment /
                          ssq-data（2083 期历史）/ sim-real（物理内核）
  src/game-logic.js       build.js 生成：index.html 的 module 主体
  src/analysis.js         build.js 生成：picker 的统计 / 权重 / 评分 / 生成算法
  src/simlog.js           build.js 生成：index.html 的 SimLog（8 项形态评估 + 持久化）
```

**`index.html`、`picker/index.html`、`picker/data.js`、`sim_real.js`、`_vendor/` 是唯一真源**，
Web 端改完执行一次即可同步：

```bash
node miniprogram/build.js
```

小游戏不支持 importmap / 裸模块名 / ES module 包加载，构建脚本把本地 `_vendor/` 的 ESM
转成原生 CommonJS，并抽取 Web 端的选号算法与 SimLog 逻辑；只做三处小游戏专属注入
（Web 源码不动）：`WebGLRenderer` 显式传入上屏 canvas、主循环按页面决定是否渲 3D、
渲染后统一叠加 UI 层。因此 Web 与小游戏共用同一份 3D 场景、物理、开奖流程、
分辨率 / 构图适配、历史数据与选号算法。

UI 层不依赖 DOM：伪 DOM 元素的 `textContent` / `className` / `disabled` 变化触发重绘，
仅在状态变化时上传纹理；**开奖页与选号/记录页共用同一张离屏画布**，切换页面不新增
纹理、不做每帧全屏 blit。开奖页触摸转 pointer 事件交给 OrbitControls；
选号页的触摸全部由页面接管（含滚动、点号、切 tab）。

### 小游戏内的选号工具

开奖页底部第三个按钮「选号」进入，三个 tab：

- **分布**：2083 期历史频次（红 33 / 蓝 16）、和值分布、冷热号与遗漏值，
  全部用 Canvas 自绘柱状图，**不引入 Chart.js**（小游戏里它要整套 DOM 适配且 >200KB）。
- **选号**：手动点号、机选一注、按历史形态评分的「智能推荐」（复用 Web 版
  `generate()` 算法）、保存选号；「本地物理摇一期」直接调 `sim_real.js` 物理内核
  在手机本地出号并写入开奖记录，**不需要电脑上的 Node 服务**。
- **记录**：SimLog 的开奖记录 + 8 项形态评估（可展开细项）+ 与已保存选号的中奖等级对比，
  数据落在 `wx storage`（`localStorage` 适配），杀掉小游戏也不丢。

`picker/sim_server.js` 仍保留给 Web 端做批量回测；小游戏可选连它同步结果：
在 `game.js` 里把 `GameGlobal.__SIM_REMOTE` 置 `true`、`__SIM_BASE` 改成 PC 的局域网 IP，
并在开发者工具关闭「不校验合法域名」。默认关闭，纯本地运行零依赖。

### 包体与内存

- 主包约 **1.7MB**（three r160 1.24MB + 历史数据 63KB + 物理内核 26KB + UI/主逻辑），
  远低于小游戏主包限额；生成物已提交，导入即可跑。
- 运行时不再有 4096 宽贴图、也不再有 98 个离屏 canvas（见上「纹理/内存」）。

### 导入步骤

1. 微信开发者工具 → 导入项目 → 目录选 **`miniprogram/`**（不是仓库根目录）
2. AppID 选「测试号」/「不使用 AppID」（`project.config.json` 里 `touristappid` 是占位，可替换）
3. 编译类型已设为 `game`；点「预览」，手机微信扫码即可运行

`game.json` 默认 `portrait`（竖屏，`fitFov` 已保证两台机器完整入画）；想要横屏改成
`"landscape"` 即可，分辨率与构图逻辑无需改动。

### 已知差异

- 小游戏版把 Web 的 60 余个 DOM 控件精简成三个 Canvas 页面，保留全部核心能力
  （分布统计 / 选号生成 / 手动点号 / 物理出号 / 记录评估 / 中奖对比），
  但不含 Web 端的批量回测、走势表格、参数滑块等高级控件。
- 程序化音效走 `wx.createWebAudioContext()`（不支持时静默降级，不影响开奖）。
  全部用「宽带噪声脉冲 + 非谐波模态」建模，**不含任何振荡器**，因此没有合成器的电子音；
  出球的「嘟」是噪声过高 Q 带通后的窄带下滑音。共八段采样：
  **搅拌**（4s 无缝循环，随拨盘转速淡入淡出，整局唯一持续的声音）、下落（1.1s，闸门抽开整批球
  落入搅拌室）、开局 / 开阀 / 出球 / 落位 / 完成 / 复位。
  搅拌只有**离散撞击**：58 颗/秒均匀铺满 4s 不成簇 + 200Hz 高通 + 一阶低通 ≈2.4kHz
  + 50ms 窗 RMS 包络压平（200ms 尺度波动 8%）+ 尾部环形折返，听不出它在循环。
  曾经叠过一层 180~3300Hz 的带通白噪声「底床」求「一直有东西在动」的质感，是错的：
  实测颗粒间隙里仍有 73% 的能量（删掉后只剩 19%）、2k~6k 从 6% 抬到 19%，
  听感是一层永不间断的「沙沙」——球本身不发声，响的只有撞击，连续性应由密度给出。
  常驻音频节点 3 个（master + 搅拌的 1 源 + 1 增益），搅拌源一直挂着、只用增益门控，
  摇奖过程中不新建节点；事件声每次 1 源 + 1 增益，播完自动回收。
  采样 22.05kHz、8 段合计 8.31s / 716KB；总音量 `VOL` 压低，只作背景提示。
  音频**预热**：合成只算出 Float32Array（不碰 AudioContext），与 `new AudioContext()`
  （约 186ms，音频线程初始化）一起放在首帧之后 `requestIdleCallback` 里做掉。
  点击「开始摇奖」时只剩 createBuffer + 拷贝（实测 0.4ms），按下的一刻没有停顿。
  事件声播完即 `disconnect()`，不靠 GC 回收节点。
  完整的设计依据、电平表、调参速查与性能实测见 [`docs/AUDIO-DESIGN.md`](docs/AUDIO-DESIGN.md)。
- 本地物理出号是同步计算，手机上约 1~2 秒，期间会先显示「计算中」提示。
- 本仓库的 `main` = 移动优化版 + 小游戏完整功能；`full-fx` 分支 / `pre-mobile-opt` tag =
  简化前的完整高画质桌面版，可用 `git checkout full-fx` 回退对比。
